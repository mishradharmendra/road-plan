# Principal Java Architect — First 6 Months Plan

Context: joining a financial firm that provides **risk analytics and market data**
as a Principal Java Architect, alongside an existing Solution Architect (SA).

## The one-paragraph strategy

Spend the first 30 days **earning context, not spending credibility**. Days 31–90,
deliver **two visible, low-risk wins** that the engineering teams feel directly
(build/JDK/observability-class problems) and co-publish Java platform standards
with the Solution Architect. Months 4–6, **own one strategic initiative end-to-end**
(most likely market-data distribution latency/resilience or risk-calc grid
throughput) with a measurable baseline and target. Throughout, operate on an
explicit split: **the SA owns "what solution solves this business problem"; you
own "how we build it well in Java, consistently, across all solutions."**

## Non-negotiables for yourself

1. No proposal to replace an existing system before Day 60.
2. Never say "at my last firm we..." — say "one option I've seen work is...".
3. Every critique of an existing design goes to its owner privately first.
4. Every recommendation carries a number: latency, cost, hours, incidents, CVEs.
5. Write things down. A principal's leverage is documents that outlive meetings.
